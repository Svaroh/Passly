| Компонент | Версія у PLAN.md | Фактична версія | Завершені результати |
|-----------|------------------|-----------------|----------------------|
| **`passly_android`** | 3.1.x | **6.0.8** (commit `daebc1379`) | **M0** та **M1 (Автономність)**: Локальне збереження секретів, неблокуючий unlock, відв'язка апаратного Keystore від біометрії, основа модуля `core/sync`. |

## 2. Реалізовані етапи

### Етап M0: Специфікація та основа синхронізації
- **Статус:** ✅ **Повністю реалізовано.**
  - Специфікація зафіксована в `passly_android/docs/sync-protocol.md` та `docs/architecture/sync-protocol.md`.
  - Модуль `core/sync` створено в `passly_android/core/sync`: містить `SyncStatus`, `SyncResult`, `SyncTrigger`, `SyncBackoff` (з тестами), `SyncStatusRepository` та `NetworkStateProvider`.

---

### Етап M1: Автономність Android (Вимоги R0, R2, R5, R6)
- **Статус:** ✅ **Повністю реалізовано (коміт `1e1aea3c4` та наступні рефакторинги).**
  - **База даних:** Створено таблицю `secrets` (`SecretEntity`), `SecretsDao` та міграцію Room `Migration28to29.kt`.
  - **Local-first читання:** `SecretInteractor` звертається до `GetLocalSecretUseCase`. Якщо запис є локально, мережеві запити не надсилаються.
  - **Неблокуюче розблокування (R6):** Реалізовано `BackgroundSignInExecutor` та `HasLocalReplicaUseCase`. За наявності локальної репліки сховище відкривається миттєво після локальної перевірки фрази; серверна сесія встановлюється асинхронно у фоні.
  - **Таймаути мережі:** Таймаут з'єднання скорочено до 10 с; загальний ліміт виклику — 60 с; PGP та RSA ключі сервера завантажуються паралельно.
  - **Безпека Keystore (R5):** Майстер-ключ сховища не скидається при зміні біометрії (без `setUserAuthenticationRequired`).

---

### Етап M2: Серверний API — Ядро дельта-синхронізації (`passly_api`)
- **Статус:** ✅ **Реалізовано та працює в продакшені.**
  - Плагін розгорнуто в `plugins/PassboltCe/Sync`.
  - Міграція БД `config/Migrations/20260812200000_V600CreateSyncLog.php` (таблиця `sync_log` із полями `seq`, `entity_type`, `entity_id`, `op`, `created`).
  - Слухач подій `SyncLogModelListener` та сервіс запису `SyncLogRecorderService` для ресурсів, секретів і прав.
  - Ендпоїнт `GET /sync/meta.json` (`SyncMetaController`, `SyncMetaService`).
  - Ендпоїнт `GET /sync/changes.json` (`SyncChangesController`, `SyncChangesService`) з підтримкою курсору `since`, лімітів, стабілізації водяного знака (2 с лаг), перевірки терміну зберігання (90 днів, `410 Gone`) та динамічної фільтрації прав.
  - Очищення застарілих записів: `SyncLogRetentionService` та команда `bin/cake sync_log_prune`.
  - Плагін `PassboltCe/OfflineMode` адаптовано для необмеженої роботи офлайн.
  - *(Ендпоїнти `/sync/bootstrap` та `/sync/manifest` перенесені до [docs/UA/TODO/roadmap-backlog.md](../TODO/roadmap-backlog.md)).*

## 3. Автономність браузерного розширення (Фаза 2 / Розділ 11a)

Усі заплановані цілі для читання та автономного робочого простору виконані:

| Крок | Запланована ціль | Фактичний стан у v6.1.0 |
|------|------------------|-------------------------|
| **E-A** | Локальні сторінки `workspace.html` та `signin.html` у розширенні | ✅ **Реалізовано.** Інтерфейс рендериться локально без звернення до сервера. |
| **E-B** | `OfflineSessionService`, локальна перевірка фрази | ✅ **Реалізовано.** Розблокування без залежності від мережі. |
| **E-B1** | Вимкнення `LocalStorageService.flush()` на старті | ✅ **Реалізовано.** Локальна копія зберігається постійно між перезапусками браузера. |
| **E-C** | Local-first шлях для читання ресурсів, профілю, груп | ✅ **Реалізовано.** Дані спочатку читаються з локального сховища. |
| **E-V** | Автоматизовані офлайн-тести Playwright | ✅ **Реалізовано.** Набір `test/offline/verifyOfflineWorkspace.js` успішно проходить. |
| **E-D** | Офлайн-стани UI у styleguide | ✅ **Реалізовано.** Фільтри, діалоги та банери адаптовані під офлайн-режим. |

### Реалізовано понад початковий план:
1. **Безшовний офлайн-роутинг (PR #45):** У разі падіння сервера розширення непомітно перемикається на локальний `workspace.html` без помилок з'єднання браузера.
2. **Offline-first Passkey:** Фільтрація облікових даних WebAuthn безпосередньо з локального сховища (`passkeyVaultResourceService`), що усуває затримки API під час автентифікації.
3. **Біометричне розблокування сховища:** Інтеграція WebAuthn User Verification (Touch ID / Windows Hello) для входу в розширення без введення фрази.
