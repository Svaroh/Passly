## 2. Детальний статус за етапами `PLAN.md`

### Етап M0: Специфікація та каркас синхронізації
- **План:** Документ `docs/sync-protocol.md`, каркас модуля `core/sync` у Kotlin, WorkManager у version catalog.
- **Факт:** ✅ **Виконано повністю.**
  - Специфікацію зафіксовано в `passly_android/docs/sync-protocol.md` та `docs/architecture/sync-protocol.md`.
  - Модуль `core/sync` створено в `passly_android/core/sync`: реалізовано `SyncStatus`, `SyncResult`, `SyncTrigger`, `SyncBackoff` (з юніт-тестами), `SyncStatusRepository`, `NetworkStateProvider`.

---

### Етап M1: Автономність Android (Вимоги R0, R2, R5, R6)
- **План:** Створення таблиці `Secret`, міграція БД Room, локальне читання секретів, локальний unlock без очікування мережі, захист ключа БД у Keystore без прив'язки до біометрії.
- **Факт:** ✅ **Виконано повністю (комміт `1e1aea3c4` та наступні).**
  - **База даних:** створено таблицю `secrets` (`SecretEntity`), `SecretsDao`, реалізовано міграцію Room `Migration28to29.kt` (початково планувалася як 23➔24, але актуальна схема була 28).
  - **Local-first читання:** `SecretInteractor` тепер спочатку звертається до `GetLocalSecretUseCase`. Якщо секрет знайдено локально, мережевий запит не виконується.
  - **Автономне розблокування (R6):** створено `BackgroundSignInExecutor` та `HasLocalReplicaUseCase`. Якщо на пристрої є локальна репліка, сховище відкривається миттєво після локальної перевірки фрази; встановлення серверної сесії GPGAuth винесено у фоновий detached-скоуп.
  - **Мережеві таймаути:** `connectTimeout` скорочено до 10 с, `callTimeout` встановлено на 60 с, ключі сервера PGP та RSA завантажуються паралельно.
  - **Аудит викликів:** `AuthenticatedOperationRunner` більше не блокує локальні дії через відсутність сесії (`requiresSession = false`); `KeyInspectorViewModel` читає локальні дані `users`; кнопка створення записів не зникає при помилці фонового рефрешу.
  - **Безпека Keystore (R5):** збережено ключ БД без `setUserAuthenticationRequired`/`setInvalidatedByBiometricEnrollment`.

### Етап M2: Серверна частина (`passly_api`)
- **План:** Плагін `PassboltCe/Sync`, таблиця `sync_log`, гачки `afterSave`/`afterDelete`, ендпоїнти `/sync/{meta, changes, bootstrap, manifest}`.
- **Факт:** 🟡 **Виконано частково (основа готова).**
  - ✅ Створено плагін `plugins/PassboltCe/Sync`.
  - ✅ Створено міграцію `config/Migrations/20260812200000_V600CreateSyncLog.php` (таблиця `sync_log` з полями `seq`, `entity_type`, `entity_id`, `op`, `created`).
  - ✅ Реалізовано слухач подій `SyncLogModelListener` та сервіс `SyncLogRecorderService` (фіксація змін `resources`, `secrets`, `permissions`).
  - ✅ Реалізовано ендпоїнт `GET /sync/meta.json` (`SyncMetaController`, `SyncMetaService`).
  - ✅ Реалізовано ендпоїнт `GET /sync/changes.json` (`SyncChangesController`, `SyncChangesService`) з підтримкою курсору `since`, ліміту, водяного знака (watermark lag 2s), обробки ретеншну (`410 Gone`) та резолюції прав доступу (відкликані права потрапляють у `deletions`).
  - ✅ Реалізовано очищення журналу: `SyncLogRetentionService` та CLI-команду `SyncLogPruneCommand` (`bin/cake sync_log_prune`).
  - ✅ Адаптовано плагін `PassboltCe/OfflineMode` для зняття обмежень за часом (perpetual offline mode).
  - ⏳ **Ще не реалізовано на сервері:**
    - `GET /sync/bootstrap.json` (`SyncBootstrapController`) — повернення початкового зліпка з пагінацією;
    - `GET /sync/manifest.json` (`SyncManifestController`) — легковажна звірка стану;
    - Спеціальний тип аудиту `sync` для завантаження секретів.

### Додаткові покращення, реалізовані понад план:
1. **Безшовна офлайн-маршрутизація (Seamless Offline Routing, PR #45):** розширення автоматично відкриває локальний `workspace.html`, якщо сервер не відповідає, без очікування браузерних мережевих помилок.
2. **Offline-first Passkey:** повноцінна підтримка WebAuthn / Passkey, що працює безпосередньо з локального сховища `passkeyVaultResourceService`.
3. **Біометричний анлок розширення:** інтеграція WebAuthn User Verification (Touch ID / Windows Hello) для розблокування сховища замість парольної фрази.
