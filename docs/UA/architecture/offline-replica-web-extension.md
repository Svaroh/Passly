# Автономне робоче середовище браузерного розширення (`passly_browser_extension`)

Цей документ описує архітектуру браузерного розширення Passly (Chrome MV3, Firefox, Safari), реалізацію автономного інтерфейсу користувача, безшовну маршрутизацію (Seamless Offline Routing) та offline-first механізм Passkey/WebAuthn.

---

## 1. Архітектурне відкриття: локальний UI розширення

У ванільному Passbolt розширення слугувало лише допоміжним ін'єкційним скриптом для веб-сайту сервера (`https://passbolt.example.com/app/...`). Якщо сервер був вимкнений, відкрити повноцінний інтерфейс робочого простору було неможливо.

**У Passly реалізовано незалежне середовище:**
- Повний інтерфейс робочого простору зібрано **всередині самого розширення**:
  - `webAccessibleResources/passbolt-iframe-app.html` (робочий простір),
  - `webAccessibleResources/workspace.html` (автономний хост),
  - `webAccessibleResources/signin.html` (локальний екран входу).
- Контент-скрипт підключає порт до фонової сторінки (`background_page`) через `PortManager` та рендерить React-компоненти `ExtBootstrapApp` з бібліотеки `passly_styleguide`.
- Таким чином, для показу паролів, навігації папками, пошуку та копіювання облікових даних **віддалений сервер не потрібен взагалі**.

---

## 2. Локальне сховище та збереження репліки

Розширення використовує безпечне сховище `browser.storage.local` та Origin Private File System (OPFS):

- `ResourceLocalStorage`, `FolderLocalStorage`, `GroupLocalStorage`, `SecretLocalStorage` зберігають повний стан акаунта.
- Секрети зберігаються в локальному сховищі в зашифрованому OpenPGP-форматі.
- Метод `FindSecretService.findByResourceId` реалізує принцип **local-first**: спочатку перевіряється наявність секрету на пристрої, а звернення до API відбувається лише для нових записів за наявності зв'язку.

### Захист від стирання репліки (виправлення E-B1):
У попередніх версіях розширення викликало `LocalStorageService.flush()` при кожному запуску браузера (`OnStartUpService`) або за таймером у разі збою опитування сервера.
**Це було повністю усунуто:**
- На старті очищаються виключно сесійні змінні (`flushSessionScoped`).
- Офлайн-стан ніколи не трактується як вихід з акаунта (`Sign Out`).
- Репліка зберігається необмежений час, переживаючи перезавантаження ОС та браузера.

## 3. Безшовна офлайн-маршрутизація (Seamless Offline Routing, PR #45)

До релізу 6.1.0 спроба відкрити робочий простір за відсутності інтернету призводила до зависання або сторінки помилки браузера:
`Unable to reach the server, you are not connected to the network`.

### Що було реалізовано:
1. **Перехоплення недоступності сервера:** `checkAuthStatusService` при помилці транспорту повертає `{ isOffline: true }` замість аварійного винятку.
2. **Миттєве перенаправлення:** якщо домен сервера не резолвиться або повертає таймаут, розширення безшовно перенаправляє користувача на локальну сторінку `workspace.html` або локальний `signin.html`.
3. **Локальна валідація фрази:** `AuthLoginController` перевіряє парольну фразу користувача локально (через WebCrypto / openpgp.js) без виклику серверного GPGAuth-челенджу.
4. **Неблокуючий QuickAccess:** спливаюче вікно QuickAccess монтується та показує записи миттєво з локальної бази, не очікуючи на завершення мережевих фонових перевірок.

## 4. Offline-First Passkey та WebAuthn

Passly містить повноцінний вбудований провайдер Passkey / WebAuthn для браузера:

- **Локальний пошук облікових даних:** під час запиту веб-сайту на автентифікацію (`navigator.credentials.get()`) розширення фільтрує відповідні ресурси Passkey за доменом (Relying Party ID) безпосередньо з локального сховища (`passkeyVaultResourceService`).
- **Нульові мережеві затримки:** усунуто фонові очікування синхронізації з API під час генерації WebAuthn Assertion.
- **Підтримка нативного WebAuthn фолбеку:** якщо у сховищі не знайдено відповідного Passkey, запит коректно передається системним ключам безпеки (YubiKey / Windows Hello / Touch ID).

---

## 5. Біометричне розблокування

У версіях 6.0.28+ додано підтримку біометрії:
- Діалог введення парольної фрази (`InputPassphrase`) у `passly_styleguide` підтримує біометричний анлок через WebAuthn User Verification.
- Сервіс `biometricAuthService` зберігає загорнутий сесійний ключ, що дозволяє користувачеві розблоковувати сховище відбитком пальця Touch ID / Windows Hello без повторного введення довгої парольної фрази.
- Написано наскрізні Playwright-тести: `scripts/test-biometric-e2e.js`.
