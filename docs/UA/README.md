# Архітектурна документація Passly

Цей каталог містить технічну та архітектурну документацію проєкту **Passly** — безпечного менеджера паролів для команд із підтримкою **автономного локального сховища** та **інкрементальної синхронізації**.

---

## 1. Головна вимога (R0) та філософія

> **Локальна копія працює повноцінно без сервера необмежений час.**

Passly проєктується не за принципом «веб-застосунку з кешем» чи «тимчасового офлайн-режиму», а як **повноцінна автономна репліка сховища**:
- Застосунок, який хоча б раз синхронізувався, **ніколи не втрачає працездатності** через недоступність сервера — ані через годину, ані через місяць, ані якщо сервер вимкнено назавжди.
- Усі критичні операції доступні локально: перегляд, пошук, копіювання паролів, генерація TOTP, autofill, passkey, робота з теками й тегами.
- **Жодного віддаленого стирання чи примусового протухання**: немає TTL для локальних даних, немає блокування через прострочену сесію/JWT/MFA, немає вимог «підключитися до мережі кожні N днів».
- Синхронізація — це **доповнення** для обміну свіжими даними між пристроями, а не обов'язкова умова доступу.

---

## 2. Структура документації

Документація розділена на такі спеціалізовані розділи:

1. [Загальний огляд системи](architecture/system-overview.md) — цілі, вимоги (R0–R8), анти-вимоги, життєвий цикл автономної роботи, структура проєктів у робочому просторі.
2. [Безпека та шифрування](architecture/security-and-encryption.md) — 4-рівнева модель захисту (E2E OpenPGP, SQLCipher, апаратні сховища ключів Keystore/Keychain/WebCrypto), захист пам'яті, аналіз загроз та політика ротації секретів.
3. [Протокол синхронізації `sync/1`](architecture/sync-protocol.md) — нормативна специфікація дельта-синхронізації: журнал змін `sync_log`, монотонний лічильник `seq`, водяний знак (watermark), ендпоїнти `/sync/meta`, `/sync/changes`, `/sync/bootstrap`, `/sync/manifest`, обробка помилок.
4. [Автономне сховище Android](architecture/offline-replica-android.md) — реалізація в `passly_android`: база даних Room + SQLCipher (таблиця `Secret`), неблокуючий вхід (`BackgroundSignInExecutor`), local-first читання, модуль `core/sync`.
5. [Автономне робоче середовище браузерного розширення](architecture/offline-replica-web-extension.md) — реалізація в `passly_browser_extension` та `passly_styleguide`: локальні сторінки `workspace.html` / `signin.html`, безшовний офлайн-роутинг, offline-first passkey, біометричний анлок.
6. [Офлайн-зміни, черга операцій та конфлікти](architecture/offline-writes-and-conflicts.md) — збереження локальних змін у черзі `pending_ops`, алгоритм вирішення конфліктів за версіями, збереження конфліктних копій у `sync_conflicts`, аварійний експорт (R8).
7. [Порівняльний аналіз: План vs Реалізація](architecture/implementation-status.md) — детальний звіт про виконання кожного пункту `PLAN.md` станом на жовтень 2026 року у всіх компонентах системи.

## 3. Зведена таблиця вимог

| # | Вимога | Технічне трактування | Статус |
|---|--------|----------------------|--------|
| **R0** | Повна автономність | Сховище доступне без сервера необмежений час; усі секрети зберігаються локально | ✅ Реалізовано на Android та в Extension |
| **R1** | Крос-платформеність | Платформо-незалежний протокол `sync/1`, спільні контракти | ✅ Специфіковано; реалізовано API та частково клієнти |
| **R2** | Повне локальне зберігання | Локальна БД містить усі ресурси й секрети; UI читає виключно локально | ✅ Реалізовано на Android та в Extension |
| **R3** | Інкрементальна дельта | Оновлення лише змінених частин за `seq` через `sync_log` | 🟡 Сервер реалізовано (`/sync/changes`), інтеграція клієнтів у процесі |
| **R4** | Кнопка примусової синхронізації | Явна дія в UI зі станом синхронізації та часом останнього оновлення | 🟡 Частково реалізовано статуси |
| **R5** | Надійне шифрування | E2E (OpenPGP) + SQLCipher / WebCrypto + системні KeyStore без біометричної інвалідації ключа БД | ✅ Реалізовано |
| **R6** | Офлайн-розблокування | Локальна валідація парольної фрази без звернення до мережі, неблокуючий вхід | ✅ Реалізовано на Android та в Extension |
| **R7** | Офлайн-зміни | Черга операцій у локальній БД, оптимістичний UI, збереження конфліктів | 🟡 Заплановано |
| **R8** | Незалежність від сервера | Експорт зашифрованої резервної копії навіть при мертвому сервері | 🟡 Заплановано |
